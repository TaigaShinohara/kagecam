# コンセプト見直し記録：KageCam v0.2.0

- 日付：2026-11-14
- 手順：concept-driven-ux スキル（既存機能の体験を改善する／コンセプト達成の最終照合）＋ experience-balance の観点を併用
- 区分：大きな変更（v0.1→v0.2 のコンセプト転換の事後審査）／範囲：見直しと報告のみ（実装は含まない）
- 審査：ディレクター（主担当）評価＋独立審査（作者の自己評価を渡さない分離入力で実施）

## コンセプト（L1）

日常の写真を持つ人が、ふと「怖い画像を作りたい」と思った時に、写真から影だけを抜き、型と調整で「気配の怖さ」を仕上げて棚に集めることで、静かな怖さを楽しみ、コレクションが育っていく体験。
- 怖さ＝気配（ジャンプスケアではない）。怖さは作品の中だけ、操作UIは静か。調整は4本まで。

## 機能ごとの評価（役割 → 提供 → 行為 → 結果）

| 機能 | 評価 | 判定 |
| --- | --- | --- |
| 棚 | 成果の置き場。空状態の一言＋2ボタンで初回の行為へ迷わず進める | 維持 |
| 撮る／選ぶ | 素材の入口。端末標準の2経路で負担小 | 維持 |
| 影抽出（輝度＋大津法） | 核の変換。自動で最初の成功が短い。ただし精度が素材依存で体験の成否を握る（独立審査 弱点2） | 維持（精度の限界は明記して付き合う。AI分離の判断は妥当） |
| プリセット3種 | 型＝世界の反転／赤／旧世界。各型と「気配」の対応が説明できる。影絵は比較と逃げ道として意味あり（削減対象ではない） | 維持 |
| 調整4本 | 残像＝気配、引き伸ばし＝不自然な比例、ノイズ＝劣化、残り具合＝抽出量。1対1で意味が通る。上限4本が効いている | 維持 |
| 保存／詳細／削除 | 保存＝確定、鑑賞と削除は成立。ただし共有・書き出しなし、再編集不可（R-2） | 変更候補（下記） |

テンションカーブ（experience-balance観点）：山場は「現れる瞬間（0.9秒フェード）」の1回に集中し、調整＝平坦な探索、保存＝区切り、棚＝静かな余韻、という流れは成立。ただし保存後に鑑賞以外の第二の山場（見せる・反応を得る）がなく、曲線が保存で終わる。

## 独立審査の結果（要旨）

総合判定：**条件付き合格**（有効範囲：v0.2.0 のコンセプトと機能構成の設計のみ。コンセプト達成の判定は含まない）

維持すべき良さ：コンセプトの出どころが実機の発見であること／怖さの定義と禁止事項がセットで暴走の歯止めになっていること／調整4本の上限／怖さの封じ込め／短い導線。

必須修正：
- **R-1（検証の未完了）**：v0.2.0 の気配の怖さが実機未確認のままコンセプト確定扱いされている。解消条件＝本人が v0.2.0 実機で複数点を作り「偶然でなく作れる」ことを確認して記録する。それまでコンセプトは「仮説」と明記する。
- **R-2（保存仕様と『仕上げる』行為の不整合）**：保存後・再編集不可＋元写真なしでは、仕上げの試行錯誤と保存の確定が矛盾する。解消条件＝(a) 元画像保持＋再編集可能にする、(b) 「一発仕上げ」を意図的コンセプトとして定義し直す、のどちらかを選び記録する。

有力な代案（独立審査とディレクターで一致）：**共有・書き出しの追加**。作品がアプリ内に閉じ、「見せて反応を得る」増幅経路がない。端末内保存のみ（サーバーなし）の制約には反しない。

弱点2（変換精度への一点依存）：輝度＋大津法は「影だけ」を保証しない（暗い被写体は残り、明るい影は消える）。コンセプトの第一文の成否が素材運に左右される。

## 維持・変更・統合・削減の比較と選定

| 候補 | 区分 | 判断 | 優先 |
| --- | --- | --- | --- |
| 共有・書き出し（詳細画面から端末標準の共有／ギャラリー保存） | 追加（変更） | 採る方向で本人判断へ。コンセプトの「作れる」の先「見せられる」を閉じる | 高（R-1の次） |
| 再編集（元画像保持） | 変更 | R-2 の選択肢(a)。本人の判断で確定 | 高（判断が先） |
| 編集画面で元写真と見比べ（長押し等） | 変更 | 採る候補。抽出の成否判断としきい値調整の根拠が画面内にない問題への手当て。効果は仮説、実装は小さい | 中 |
| 影絵プリセットの削減 | 削減 | 採らない。比較と逃げ道の役割がある | ― |
| オンボーディング追加 | 追加 | 採らない（当面）。導線が短く空状態で代替できている | ― |
| 効果・プリセットの追加 | 追加 | 採らない。4本上限と「気配」の定義を守る | ― |

確かめる順序：①R-1（本人の v0.2.0 実機確認。ここが崩れると他全てが無意味）→ ②R-2 の判断 → ③共有の実装判断 → ④見比べ。

## コンセプト達成の最終照合（対象版：v0.2.0）

| コンセプトの要素 | 最終成果での実現内容 | 根拠 | 判定 |
| --- | --- | --- | --- |
| 誰が・場面：写真を持つ人が怖い画像を作りたい時に | 空の棚→2ボタン→自動抽出まで迷わない導線 | 動作確認＋審査 | 部分的に実現（v0.2 の人間の観察なし） |
| 何をして：影だけを抜く | 輝度＋大津法のマスク抽出を実装 | 動作確認（ビルド）＋審査 | 部分的に実現（精度は素材依存） |
| 型と調整で仕上げる | プリセット3種＋調整4本、即時反映 | 動作確認＋審査 | 実現（設計・動作レベル） |
| どんな気持ち：気配の怖さを楽しむ | v0.1 で本人が「いい感じに怖くなる」と発見。v0.2 の効果群の実感は未確認 | 人間の観察（v0.1 のみ） | 未確認（R-1） |
| 棚に集めて育つ | 日付つきグリッドで蓄積。ただし見せる経路がなく増幅は自己完結 | 動作確認＋審査 | 部分的に実現 |

未実現・未確認：R-1（怖さの再現性、人間の観察待ち）、R-2（保存の設計判断待ち）、共有なし（変更候補として本人判断待ち）。この見直し自体は「見直しと報告」で完了し、案件（コンセプト確定）は R-1・R-2 の解消まで完了にしない。

## 解消記録（2026-11-14）

- 本人が選択肢で「v0.3で再編集＋共有を入れる」を選択。
- **R-2 解消**：選択肢 (a) を採用 ― v0.3.0 で元画像（抽出用に縮小した写真）と調整パラメータを作品と一緒に端末内へ保存し、詳細画面「怖くし直す」からパラメータを復元して再編集→上書き保存できるようにした。v0.2 以前の作品は元画像が無いため再編集対象外とし、詳細画面に理由を一言表示する（保存済みデータは壊さない）。
- **共有・書き出し 解消**：詳細画面に「共有する」（端末標準の共有シート、画像PNG）を追加。サーバーなし・端末内保存のみの制約には反しない。
- **R-1 は未解消のまま**：本人の v0.2.0 以降での実機確認（複数点を作って「偶然でなく作れる」か）がまだ。コンセプトは引き続き「仮説」として扱い、本人の感想が届いた時点で照合を更新する。
