# KageCam オンボーディング設計（mobile_onboarding スキル適用・設計案）

- 状態：設計案（2026-11-15）。独立審査と本人の実装範囲の選択を経てから実装する
- 前提：現行の KageCam（v0.7.0）にオンボーディングは無い。初回は空の棚と「最初の怖い影を探しに行こう」だけ

## コンセプトの読み取り（正本は ART_DIRECTION.md 2.4 §0）

- コンセプト：写真を持つ人が、自分の写真に実在した影を剥がし取り、型と調整で怖く仕上げ、その場の音を添えて、気配のホラー体験を楽しむ
- 差別化の芯：生成しない。実在した影を、剥がす。（3柱＝実在性・決定性・端末内完結）
- 解決する困りごと：ふつうのカメラは「写っているもの」を残すだけ。被写体を消して気配だけを残す手段がない
- 解決後のいちばんの変化：写真の見方が変わる（日常で「影」を探す目になる）
- 最初の小さな成功：最初の1点を怖く仕上げて棚にしまう瞬間。オンボーディング内では試し操作で「影が残る」を先に体験させる
- 頻度：思い立ったときの単発利用。初回で「撮る→怖くする→しまう」が分かれば反復に移れる

## 4つの達成条件（このオンボーディングの具体化）

- 何のためのアプリか（言い直し文）：「写真から影だけを剥がして、怖く仕上げて集めるカメラ」
- スリーステップ：①撮る ②怖くする ③棚にしまう
- ワクワクの山場：試し操作（本物の抽出がその場で動く、11〜12ページ）＋マッチ宣言（3ページ）。最後だけに置かない
- 早く使いたい：接続ページの主ボタンは「撮る」でカメラへ直行し、本体の最初の成功に直結させる

## 選択とマッチ（答えの使い道まで）

- 質問（2ページ）：「どんな影を、集めたい？」選択肢は次の4つ
  - とにかく怖い影 → マッチの根拠「怖さの型が3つある」。価値は「仕上げる」を先に
  - 静かできれいな影絵 → マッチの根拠「型『影絵』がある」。**最初の編集画面の初期プリセットを「影絵」に反映する**
  - その場の音も、一緒に残したい → マッチの根拠「撮影すると音も自動で付く」。価値は「音」を先に
  - まだわからない → マッチは断定せず「まずは1つ、剥がしてみよう」
- 回答は端末内にだけ保存し、初期プリセットと価値ページの順序に使う。それ以外には使わない

## スキルからの意図的な適応（世界観との衝突の解消）

- スキルの標準は「弾む」反応と「選択肢が震える」演出だが、KageCam のアート方針は震え・点滅・急な出現を禁止し、動きは遅いフェードだけと定める。ここでは反応を「遅いフェード＋触覚＋短い言葉」に置き換える（スキル自身の「動きを減らす場合の代替」「語調はアプリ全体でそろえる」に沿う適応）
- 称賛の語調は静かなホラーに合わせる（例：「いい影だ」）。空の称賛（すごい・えらい の連呼）はしない
- 触覚は Android の標準フィードバック（選択＝軽く、成功＝CONFIRM）を使い、端末設定に従う

## 実装メモ

- 遷移は Jetpack Compose の HorizontalPager（標準のページ送り）。独自ジェスチャーは作らない
- 試し操作のサンプル写真は、コードで描いた場面（空のグラデ＋地面＋木と人の黒い形）を Bitmap 化し、本物の ShadowExtractor に通す。つまみは本物の「影の残り具合」
- 試した影を「棚にしまう」と、本物の作品として ShadowStore に保存される（最初の成功を本物にする）
- 状態は SharedPreferences：完了フラグ（版つき）、選択の回答、初期プリセットへの反映

## 独立審査の結果（2026-11-15、条件付き合格）

有効範囲：ページ構成の大枠・選択とマッチの骨格・権限と接続の配置・所要時間。必須5件を解消しない限り実装に進めない。

### 必須と解消方針（パソパソ案）

1. **12ページの役割二重（結果＋期待）** → 役割は「結果」に一本化する
2. **価値ページの並べ替えが地図未確定** → 仕様を確定：価値3枚は A仕上げ／B音／C端末内。選択「音も一緒に」→ B,A,C の順、それ以外は A,B,C。ページ番号は表示しない（窓ドットのみ）ため番号の扱いは不要
3. **合成サンプルの影を本物の作品として保存する設計が「実在性」と衝突** → 試した影は保存しない形に変える。12ページの補足は「本番は、あなたの写真で」にし、最初の成功は接続ページからの実撮影に委ねる。サンプルの合成自体は可（抽出処理は本物）
4. **選択の反応時間（250〜400ms基準）が未定義** → 反応専用の長さを定義：選択の反応は300msフェード＋触覚＋短い一言。ページ主役の900msフェードとは別物とする
5. **常時アニメーションとアート方針の衝突** → アート方針に「オンボーディング例外」を追記する案：オンボーディングに限り、呼吸のような緩やかな動き（伸縮・グラデの移動）だけを認める。震え・点滅は引き続き禁止。14ページの「ボタンが脈打つ」は落として静止＋フェードにする

### 推奨（審査より）

- 称賛文をページ別に設計し、言い回し3通り以上＋直前の再使用回避を状態で持つ
- 13ページ「許可する」にも最小の「小」反応を付ける
- 試し操作が後半に寄る理由を記録する（ステップで操作を理解してから試す方が成功しやすいため）
- 窓ドットの仕様（1ページごとに必ず1つ動く・圧縮ドット禁止）を明記する
- 計測はしない（端末内完結の柱のため）と理由を記録する
- 読み上げの順序と、動きを減らす設定では常時アニメーションを止めることを明記する

## 最終仕様（2026-11-15 本人が「B：必須＋推奨も全部入れて実装」を選択 ― v0.8.0 で実装）

### 必須の解消（確定形）

1. 12ページの役割は「結果」に一本化（期待の要素は接続ページが担う）
2. 価値ページの並べ替え仕様：選択が「音」→ [音／仕上げ／端末内]、それ以外 → [仕上げ／音／端末内]。ページ番号は表示しない（窓ドットのみ）ので番号の扱いは不要
3. 試した影は保存しない。12ページの補足は「本番は、あなたの写真で」。最初の成功は接続ページからの実撮影に委ねる
4. 反応の長さ：選択の反応＝300msフェード＋触覚（CONFIRM）＋褒め言葉1行。ページ主役の900msフェードとは別に定義する
5. 常時アニメーションはアート方針2.5の「オンボーディング例外」で正式化：呼吸（伸縮）とグラデの緩やかな移動だけを認める。14ページの「ボタンが脈打つ」は落とし、静止＋フェードにする

### 推奨の解消（確定形）

- 褒め言葉：選択の反応用3通り（「いい目をしている」「その影、きっと似合う」「影を見る目だ」）と結果ページ用3通り（「いい影だ」「気配が、残った」「静かに、怖い」）を用意し、直前の再使用を避けるインデックスを端末に保存して回す
- 13ページ「許可する」にも最小の反応（軽い触覚）を付ける
- 試し操作を後半に置く理由：ステップ（8〜10）で操作の型を先に理解してから試す方が、本物の抽出で「できた」を感じやすいため（意図的な配置として記録）
- 窓ドットの仕様：最大5つ表示、1ページ進むごとに窓は必ず1つだけ動く、圧縮ドット（端を小さく潰す表現）は使わない
- 計測はしない：端末内完結（3柱）のため、ページ表示・離脱・回答の外部送信は行わない。端末内に残すのは完了状態・回答・褒め言葉の回し位置だけ
- アクセシビリティ：主張は見出しとして読み上げ順序に載せる。端末の「動きを減らす」設定（アニメーション時間スケール0）では常時アニメーションを止め、フェードも短くする。窓ドットには「全Nページ中Mページ目」の読み上げラベルを付ける

### 実装上の決定

- 遷移は HorizontalPager（スワイプ可）。表示ページは画面タップでも次へ進める
- 選択肢の文を少し場面寄りに調整：「ぞっとする、怖い影がほしい」「静かできれいな影絵がいい」「その場の音も、一緒に残したい」「まだわからない」。マッチの映し返しは文法が崩れないよう選択肢ごとに言い回しを用意する（原文の機械的な差し込みはしない）
- 権限ページの補足は1主張に絞る：「音は端末の中だけ。外には出ません」
- ステップ2の補足を「まず型、つまみはそのあと」に変え、価値Aの補足との重複を避ける
- 完了の保存：SharedPreferences に版（1）・回答・初期プリセット反映済みフラグ・褒め言葉の回し位置。再表示は版が上がった時だけ。棚の「はじめかた」からいつでも見直せる
